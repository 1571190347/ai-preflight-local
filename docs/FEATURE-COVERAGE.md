# 功能覆盖与检测边界

本工具面向个人在自己的计算机上运行。它参考 [ip.net.coffee](https://ip.net.coffee/) 的公开功能类别，独立实现检测界面、逻辑和卡片素材；不调用该站的私有接口，不复制其数据库、专有评分、图像或页面代码。本文记录 2026-09-09 的功能范围，第三方规则和接口可能改变。

“支持”表示提供相应操作入口和处理逻辑，不表示所有第三方服务已经在你的网络上验证成功。未配置、被限流、无法跨站读取、响应格式不兼容或没有数据，都应显示具体原因或“无法确认”，不会按“通过”处理。

## 对照表

| 公开功能类别                        | 本地版对应能力                                                         | 运行条件与解释边界                                                                                  |
| ----------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| IPv4 / IPv6、公网 IP、隐藏 IP       | 分别查询 IPv4、IPv6 和 HTTP 出口；提供显示遮罩                         | 需要请求所选出口服务。隐藏 IP 是屏幕显示功能，不会向查询服务隐藏 IP                                 |
| 地区、城市、经纬度、时区            | 按来源显示 IP 地理信息                                                 | 地理数据库是近似定位，不是设备 GPS；不同来源可能不一致                                              |
| 多线路、分流出口                    | 并列展示浏览器与本地服务请求所观察到的出口                             | 目标、协议、代理策略不同，出口可能不同；不得用本站出口替代所有目标站出口                            |
| Claude 环境检查                     | Claude 边缘 trace、HTTP 连接、官方状态和支持地区资料入口               | trace 不保证可用；不能读取 Claude 内部风控、账号状态或登录会话                                      |
| ChatGPT 环境检查                    | ChatGPT 边缘 trace、网站/API 连接、官方状态和支持地区资料入口          | API 未认证响应只证明收到 HTTP 响应，不能证明有模型权限；不读取账号 Cookie                           |
| Cloudflare trace                    | 显示来源及返回的 trace 字段                                            | Cloudflare 通用节点和具体平台节点是不同观察点；不生成 TrustScore                                    |
| TrustScore、账号封禁风险            | 用来源明确的事实和“无法确认”说明替代不可验证评分                       | 不提供 Claude/OpenAI 私有信任分、封号概率或“保证安全”结论                                           |
| AI 易读报告                         | 将本次结论、环境事实、数据覆盖、逐项证据和建议输出为脱敏 Markdown      | 自动隐藏公网 IP，要求 AI 区分事实与推测，只给出符合官方规则的排查建议；分享前仍需检查组织和地区信息 |
| ASN、运营商、组织、住宅/机房        | 显示来源给出的 ASN、组织与网络类型                                     | 不把 ISP 自动等同于住宅；缺失字段保留未知                                                           |
| 原生 IP、VPN、代理、Tor、爬虫、滥用 | 查询提供方的类型和风险标记                                             | ipapi.is 完整标记需要自己的密钥；不根据地理信息推导“原生 IP”                                        |
| 任意 IP、多源画像                   | 输入公网 IPv4/IPv6，独立选择 ipapi.is、ipwho.is、AbuseIPDB、Shodan     | 每家服务接收被查询 IP；不查询私网、环回和保留地址                                                   |
| IP 风险分、举报、黑名单             | 显示 ipapi.is 原始风险字段、AbuseIPDB 举报置信分与记录时间             | 各家评分定义不同，不合成为平台评分；“未标记”不等于无风险                                            |
| 开放端口、主机名、漏洞线索          | 查询 Shodan InternetDB 的已收录数据                                    | 被动读取历史观测，不执行主动端口扫描；404 表示没有记录                                              |
| 国内外网站连通与延迟                | 对所选站点执行三轮请求，显示单次结果和中位数                           | HTTP 完成耗时不是 ICMP Ping；浏览器 CORS、缓存、代理和服务响应均会影响结果                          |
| DNS 快速/深度检测                   | 配套自建权威 DNS 收集器，生成 3 或 10 个随机测试域名                   | 需要自己的域名委派、公网 DNS 服务器和 HTTPS API；未配置时明确标记                                   |
| DNS 解析器、地区                    | 显示权威端实际看到的递归解析器，并可继续查询其 IP 画像                 | 观察到的是向权威端查询的解析器，未必是设备上配置的 DNS；地理差异本身不是泄露证据                    |
| 本机 DNS 与网卡                     | 读取运行 Node 服务的计算机的系统解析结果、配置解析器及接口             | 不等同于浏览器 DoH、移动设备或代理内部 DNS；仅在用户主动运行后读取                                  |
| WebRTC 多 STUN、出口比较            | 从配置的多个 STUN 收集可见 ICE 候选，与 HTTP 出口并列比较              | 无候选可能来自浏览器保护或网络限制；不同出口只作为排查线索                                          |
| 全球 Ping                           | 可选 Globalping，最多 20 个探针，显示最小/平均/最大延迟等返回结果      | 测的是远程节点到目标；公共测量按公开信息处理。可改用自己控制的节点                                  |
| 服务状态、分类、故障、排序          | 内置 31 个状态源，按分类查看状态和事件                                 | 默认使用兼容 Statuspage 的 JSON；非兼容状态页提供官方链接并显示无法确认                             |
| WHOIS：域名 / IP / ASN              | 基于 IANA 引导表的 HTTPS RDAP，另提供 TCP 43 WHOIS 回退                | 注册局可能限流、隐藏信息或不支持协议；WHOIS 明文传输查询内容                                        |
| 可搜索顶级域名                      | 从 IANA RDAP 域名引导表加载并筛选后缀                                  | 列表表示有 RDAP 引导的后缀，不声称覆盖所有可注册名称或可用性                                        |
| 时区、语言、系统、浏览器            | 本地浏览器能力和环境摘要                                               | 浏览器报告可能经过简化或隐私保护，不依据语言/时区给用户打风险分                                     |
| 触屏、网络信息、DNT、WebGL、Canvas  | 主动执行本地能力检查和指纹演示                                         | API 不支持或被阻止时显示未知；演示值不上传，不作为跨站身份标识                                      |
| 本地历史、清空                      | 可选保存本地脱敏摘要，支持删除                                         | 默认结果只在内存；不包含云同步。清除浏览器记录不会删除已下载文件                                    |
| AI 资讯分类与分页                   | 按配置 RSS/Atom 来源筛选和分页，跳转原文                               | 只在手动加载时联网；默认提供 OpenAI News，可自定义订阅源，不复制付费全文                            |
| IP 卡片、随机样式、贴纸、导出       | 22 种主题、8 种原创几何纹样 × 8 种印章（64 种组合），本地 SVG/PNG 导出 | 素材独立绘制，随机组合在本地完成；屏幕预览可选择显示 IP；下载时强制遮罩 IP                          |
| 动态访客 IP 嵌入代码                | 提供静态卡片输出用于分享                                               | 不实现自动收集访客 IP 的远程卡片端点；静态输出不会随访客改变，也不产生访客跟踪请求                  |

## 需要自行准备的能力

| 能力                     | 需要准备                                                  | 未准备时的行为                       |
| ------------------------ | --------------------------------------------------------- | ------------------------------------ |
| 基础浏览器检查、卡片生成 | 本地 Node.js 运行环境和浏览器                             | 无需外部账户                         |
| 公网 IP、地理与连通查询  | 能访问选定数据源的网络                                    | 显示错误或未知，保留已取得的其他结果 |
| ipapi.is 完整安全字段    | 本机环境变量 `IPAPI_KEY`                                  | 匿名查询仅返回基础归属与地理信息     |
| AbuseIPDB 举报查询       | 本机环境变量 `ABUSEIPDB_KEY`                              | 显示未配置，不提交举报               |
| DNS 权威观测             | 自己控制的域名、域名委派、公网 DNS 服务、HTTPS API 和令牌 | 不伪造解析器或套用本机系统 DNS 结果  |
| 全球探针                 | 主动选择公共 Globalping 或配置自己的节点                  | 不自动提交任何测量                   |
| 更多资讯和状态源         | 在 `config.local.json` 中配置 HTTPS 来源                  | 未配置来源不会被后台抓取             |

## 数据源说明

- **ipapi.is**：匿名与带密钥的响应字段不同。安全标记依赖密钥；空值、字段缺失和 `false` 必须区分。匿名额度与限流策略以 [开发者文档](https://ipapi.is/developers.html) 为准。
- **ipwho.is**：核对时 Free 端点允许商业使用，每日 1,000 次，不含 Security 数据；不要按文档的完整示例假定免费响应含 VPN/Tor 标记。见 [接口文档](https://ipwhois.io/documentation)。开源的是本项目代码，第三方数据库不随之获得再分发许可；见 [服务条款](https://ipwhois.io/terms)。
- **AbuseIPDB**：本项目仅使用 Check 查询。`abuseConfidenceScore` 是提供方依据举报计算的置信分，不是 AI 账号处罚预测。见 [API 文档](https://docs.abuseipdb.com/)。
- **Shodan InternetDB**：端口和漏洞线索来自已收录资料，受其范围、更新时间和使用条款约束。见 [接口文档](https://internetdb.shodan.io/docs)。
- **Globalping**：本项目每次最多请求 20 个节点。核对时匿名 API 限额为 50 探针/次、250 tests/小时；每个探针的测试计入额度。目标和结果应作为公开测量处理。见 [官方 API](https://globalping.io/docs/api.globalping.io) 与 [官方项目](https://github.com/jsdelivr/globalping)。
- **RDAP**：通过 [IANA 域名引导表](https://www.iana.org/assignments/rdap-dns/) 找到注册信息提供方，不从商业 WHOIS 聚合站反向抓取。

## 验证状态的读取方式

本地逻辑测试、类型检查、构建和浏览器界面检查，只能证明其覆盖的本地行为。真实 IP 数据库、31 个状态源、RSS、RDAP/WHOIS、浏览器 STUN、公共 Globalping 和公网 DNS 委派必须分别在使用者的网络与配置下验证。未取得实际响应的接口不得在发布说明或视频里描述成“全部实测通过”。

“收到响应”“未配置”“无法确认”与“需注意”具有不同含义。即使所有可见检查都通过，本工具仍无法得知 Claude 或 OpenAI 内部的账号判断依据。
